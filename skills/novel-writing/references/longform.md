# 长篇创作与共享书目录

## 进入一本书

先确定书根绝对路径。每个独立会话用自己的稳定标识（优先运行时会话 ID），由首次建账的会话担任主编。用户在别的会话说「加入这本书」时，读取同一书根，运行 status，再读本章材料或领取公开任务。角色和任务以书上记录为准。

下面用 PowerShell 演示，参数之间用空格隔开。用实际书根和本次命令输出替换示例变量。每次命令检查退出码；失败时读取错误再操作。

```powershell
$book = 'D:\小说\潮生'
$tool = 'C:\Users\<你的用户名>\.dsh\bundles\novel-mode\skills\novel-writing\scripts\book.mjs'
$node = 'C:\Users\<你的用户名>\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe'
& $node $tool $book status
```

新书先建书根文件夹，运行 `init <本会话标识> 0`。多个会话同时初始化时，返回的 editor 指明唯一主编。已有账本直接 status。旧书想加入协作时，核对 03、现有正文和最近一章的结尾，核实最后连续定稿章号 H，再 `init <主编> H`。如目录有缺章、重复编号或待修改稿，先核对边界。原章名、目录、旧稿和伏笔编号保留；卷表指向旧路径，新章从 H+1 接续。首次 init 会将旧 03 中清楚记录了来源和剩余 1–10 章的有效授权迁入账本，移除旧开关。来源不明时暂停。重复 init 保留已有账本的授权。

## 全书规划与每章阅读

1. 读取用户材料，保留原始要求。按目标总字数和章节字数估算章数，将每卷的字数预算、核心冲突、卷终变化与预计章号写进 01 的卷表。例如 40 卷 × 100 章 × 2500 字约为一千万字。实际卷长可以不同。远期卷只写目标；细化当前卷及即将到来的转折。第一次开篇仍按原规则确认大纲和文风。
2. 根目录 00 保存创作要求，01 做全书卷表，02 保留硬规则和实体索引入口，03 保存当前位置、近期交接、待决问题、下一步和本卷累计字数，04 保存现行文风。长表下沉到分卷与实体分档。旧书的大文件可用标题搜索和行区间定位，逐步建立索引。
3. 新卷使用 `分卷/V001/卷纲.md`，卷内按幕或每 10–20 章分段，例如 `分卷/V001/章纲/C000001-C000020.md`。正文使用 `章节/V001/C000001.md`，首行写真实章号与标题。全书章号单调递增，换卷不重置。每章用一张 `分卷/V001/章卡/C000001.md` 记录结果、人物知情边界、时间地点、伏笔、承接段和实际字数。
4. 人物、组织、规则、物件和伏笔使用稳定编号与分档路径，例如 `设定/人物/P007.md`、`设定/伏笔/F021.md`。主编分配正式编号；协作者提出新事物时使用任务键加本地序号，合稿时统一。伏笔埋设时把编号、来源章和预计回收窗口写入目标卷的 `分卷/Vxxx/待回收.md`；无预定卷的记入 `设定/待排伏笔.md`，定下目标卷后转入对应清单。延期或回收时同步两端，保留实际回收章。
5. 每章开写或中断续写时，读取 status、00 的相关约束、01 当前卷条目、02 硬规则、03、04、当前章纲、前一章卡与收尾原文、本章涉及的实体档和到期伏笔。跨卷再读上一卷的卷末交接。证据不足时按 ID 或章号检索并补读来源章节。上下文压缩后按同一路径重建。
6. 每卷结束把实际字数、主线转折、人物状态和知情边界、未回收承诺及其下一窗口写入卷末交接。主编核对全书累计、时间线和跨卷依赖，更新 01 卷表、03 与下一卷卷纲。最终逐卷核对未决项并标明开放结局。

## 审阅与写作授权

用户未指定时按 5 章授权：确认开始或继续长篇后执行 `grant 主编 REV batch 5 "用户原话"`。批满汇总，等用户确认下一批；明确要求只写一章时用 single。

主编从 status 读取 editor、rev（当前版本）、head（最后定稿章号）、mode 和 remaining。授权命令只在收到用户确认后运行；新会话加入、接任务和刷新状态都不增加额度。

| 用户指令 | 主编操作 |
| --- | --- |
| 明确只写一章／逐章确认 | `grant 主编 REV single 1 "用户原话或消息标识"` |
| 连写 N 章 | `grant 主编 REV batch N "用户原话"`，每章完成后才启动下一章正文 |
| 明确指定 N，并行分章起草 | `grant 主编 REV parallel N "用户原话"`，独立章可并写草稿，有因果依赖的场景等上游定稿 |
| 暂停／取消／剧情分叉需要决定 | `stop 主编 REV`，通知进行中的作者，保留草稿，稍后按用户答复重新授权 |

三种模式都允许多人并写当前章的不同场景。每批最多 10 章。用户只说「开一堆子代理」时，按当前授权拆场景、对白、考据、伏笔核查或审读。每次 publish 自动扣一次；edit 修稿不扣。single 定稿后调用 chapter_review；batch / parallel 在批内每章单行报告，剩余为零时汇总并暂停。用户在其他独立会话明确要求全书暂停时，那个会话也能执行 `pause 本会话标识 REV "用户暂停原话"`；遇到版本冲突先核实最新 head，再落实仍有效的暂停指令。用户改刚交付的章节时，用 edit 修订原章、章卡和受影响的设定／卷纲，再交付审阅。

## 检查与备份

用户说「查伏笔」时运行 `book.mjs 书根 check`。它读取各卷待回收表及全书待排表，用最后已定稿章号与计划章或窗口末章比较。已到期且仍开放的记录列入 planPassed；overdue 同时纳入显式标记逾期者。unplanned 列出待排／空计划；格式无法识别的行单独提示来源行号。

用户说「备份」时运行 `book.mjs 书根 backup`，在 协作/备份/UTC时间戳 下生成完整书目录快照，排除历次备份。60 分钟内再次调用返回最近一次的路径；明确需要立即再备一份时传 --force。定稿与账本在同一写锁下快照；要同时冻结手写的未交草稿，先让作者保存并暂停编辑。恢复时将快照复制到新的书目录，再运行 status。

统计字数用 `wordcount.mjs 书根`（排除 Markdown 标题、围栏代码、标点和空白，按 Unicode 字母与数字计数）。比较文风用 `style-sample.mjs 书根 [V002]`，抽取首卷和目标卷的章稿片段；给 UTF-8 参考文件则按位置抽样。所有脚本都在本技能 scripts/ 中。用户只需表达意图。

## 主会话、子代理与其他独立会话

1. 主编划分互不覆盖的任务键，例如 `V002-C000101-S01`（第一个场景）、`V002-C000101-伏笔审读`。任务说明给出书根、章号、读哪些文件、场景起止状态、视角与知情边界、字数、不得揭晓的情节、交稿要求。不同作者写相邻场景时先约定交接动作或台词。
2. 发布共享任务用 `offer 主编 REV 键 "任务说明" [全书章号]`。**凡是起草正文都传章号**；考据、审稿、规划可省略。用 `subagent` 分派可独立执行的任务，同一轮发起多个，有必要继承讨论时用 `subagent_fork`。传书根、脚本路径、角色和任务键。用当前宿主提供的 list_agents、wait_agent、send_message 跟进。并发数量服从宿主可用能力；工具不可用时说明现状，保留可由另一个会话领取的公开任务。
3. 独立会话和子代理都用 `tasks open` 找任务，`task 键` 查看说明，`take 键 自己的标识` 原子领取。已被领取时改领别的任务。若主编已通过消息分好了工，可直接 `claim 键 自己的标识 [全书章号]`。相同键只会有一位持有人。任务列表每页 50 条，下一页传偏移量，如 `tasks ready 50`。
4. 领到 token 后建 `协作/草稿/<token>/`，只在里面写自己的文件。交稿可将场景正文、事实变化、待决问题合成 `稿.md`，运行 `submit 键 token 稿.md`。任务转为 ready，账本保存不可变的交稿快照。只回传键、摘要和需主编决定的问题。若子代理没有书目录的写权限，可把文本回传父会话，由父会话代领对应任务、写入草稿并 submit。不得代扣章数。
5. 主编用 `tasks ready` 和 `task 键` 收稿，核对前章落点、人物知识、时间、伏笔和文风，统一叙述声线，删除重复交代，补齐场景衔接。跨章并行时，前章最终结尾与后章假设有冲突就退改对应场景。需要第二版时创建带修订号的新键，如 `…-S01-r2`，保留原始交稿。独立会话无需共享聊天历史。

## 定稿与修订

主编先读 status，用实际 rev 和章号运行 prepare。例如 head=100、rev=8 时：

```powershell
& $node $tool $book prepare 主编A 8 publish 101 2 '设定/人物/P007.md' '分卷/V002/待回收.md'
```

命令返回 manifest 的绝对路径，以及每份副本的 source。它自动带上正文、章卡和 03，并记录目标文件原始哈希。所有副本位于 `协作/合稿/<本次编号>/`；已有文件带旧内容，新文件为空。编辑这些副本，在同一次提交里带上本章产生的设定、伏笔、索引或文风调整。正文第一行写章号、标题；更新 03 的剧情位置、下一章计划与字数。使用 `prepare 主编 REV edit '01-大纲.md' …` 可初始化 00–04、修订旧章或维护规划。

在 manifest 的 tasks 数组填入采用的任务键。若 task.base 与当前 rev 不同，重新核对该任务依赖的前章及实体档，修改合稿；复核完毕后才在 manifest 加 `"reviewedAt": {"任务键": 当前rev}`。最后运行：

```powershell
& $node $tool $book commit 主编A '实际返回的清单绝对路径'
```

成功后用返回的 head、remaining、mode 交付。冲突时重新读 status，取新的工作副本，合并差异并复核；已存在相同章号时先读已定稿内容。禁止只改 rev 或 before 强行覆盖。作者继续创作期间，所有会话都通过脚本提交正式文件。主编标识用于协作分工；同一用户直接编辑文件仍有写权限。

## 断线、交班和恢复

- 主编重开会话先读 status 和 tasks，各作者按 token 找回自己的草稿。若作者退出，核实任务仍为 active 后用 `reassign 键 旧token 新作者`；新作者取得新 token，旧 token 随即失效。需要时只读旧草稿作参考。
- 更换主编用 `transfer 账本中的旧主编 REV 接任会话标识`，依据用户交班指示执行。它保留章号、额度和在途任务；接任者先复核基线。不会因为另一个会话刚打开就自动接管。
- commit 先把全部目标内容与进度记入 SQLite 事务，再把 Markdown 逐个原子替换。脚本中断后先运行 status，会在返回前补齐未完成的文件。若上次已成功，重试旧清单会被版本检查拦下。遇到磁盘不足或文件占用，解除原因后再次 status。
- 若有人绕开账本改了正在恢复的文件，脚本会停下并报路径。用 pending 查看提交前后哈希，另存外部编辑的副本；核对后恢复到提交前或预期提交后的准确内容，再运行 status 回放。之后通过 edit 合回外部改动。已有 SQLite 和稿件均保留。
- 多会话须能读写同一个本机书目录。异机各取一份副本或使用会产生冲突副本的同步盘，不能共享这份任务锁和授权状态。
