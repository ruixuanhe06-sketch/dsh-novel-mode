# 小说创作工作手册

以章为单位保存与定稿。用户确认开始或继续后，短篇默认 single 1；长篇用户未指定时按 5 章授权（grant 主编 REV batch 5 "用户原话"）。用户指定一章或其他章数时遵从其要求，每批最多 10 章。批满后等待新的确认，不自动续批。

## 先选择写作流程

普通单会话使用下列第一至七节。需要几十卷、百万／千万字规模、子代理写作或多会话合著时，打开本技能的 `references/longform.md` 和 `references/templates.md` 的长篇模板。运行脚本 `scripts/book.mjs`。按 01 中的卷表、分卷目录和用户意图识别长篇；账本也供短篇使用。委派消息里的角色、书根和任务键决定协作者入口；先接任务，避免重复建书。

长篇用分卷文档、实体分档与章卡落实第二节的设定规则，用共享账本落实第四节的写作授权，用 prepare / commit 落实第五节的保存和更新。只有用户点名并行分章且给出章数时，可提前起草已授权的独立章节。第三节的文风与第六节的自查同样适用。

**建书别手抄模板**：骨架用脚本一次生成，包括 00–04、设定分档、每卷卷纲／章纲／章卡／待回收表与空章节目录，可选同时建账本：

```
node scripts/new-book.mjs <书根> --title 书名 --volumes 7 --chapters 45 --words 3000 --init-ledger
```

只建骨架不写正文；已存在的文件默认跳过（要覆盖加 `--force`）。建完再填 00/01/02/04 的「待填」项。

## 一、作品目录

每部小说一个目录（默认当前工作目录下以书名命名）：

```
<书名>/
  00-创作说明.md      用户的灵感、题材、要求（原文 + 整理），以及交付方式偏好
  01-大纲.md          章节清单：标题 / 目标事件 / 预计字数 / 伏笔安排
  02-设定圣经.md      ★跨章上下文：人物、世界观、时间线、伏笔登记表、名词表
  03-进度日志.md      账本入口 + 进度、剧情位置、未回收伏笔、下一章计划
  04-文风设定.md      ★文风档案：视角、句长节奏、用词、对白比例、标点排版、钩子手法、忌用项
  参考资料/           用户提供的参考作品（只作抽样阅读，原文不进入产出）
  章节/第NN章-<标题>.md
```

模板见 `references/templates.md`（相对本技能目录；用文件读取工具打开后照抄）。
用户提供了大纲文件时，先读原文再转写进 `01-大纲.md`，不要另写一套相互矛盾的设定。

## 二、设定圣经（02）——跨章事实的唯一权威

任何一章开写前都必须重新读取 `02-设定圣经.md`、`03-进度日志.md` 与 `04-文风设定.md`。

| 区块 | 记什么 | 什么时候更新 |
| --- | --- | --- |
| 人物 | 身份、性格（含缺点）、动机、说话方式、外貌特征、当前状态与所在位置、人物关系 | 人物首次登场、状态或关系变化时 |
| 世界观 | 规则、势力、地理、时代、力量体系及其代价 | 新设定出现时 |
| 时间线 | 事件发生的先后与间隔、当前故事时间点 | 每章结束时 |
| 伏笔登记表 | 编号、埋设章、内容、计划回收章、状态（未回收/已回收/已放弃） | 每埋一个、每回收一个 |
| 名词表 | 专有名词、称谓、道具、招式、地名的统一写法 | 新名词首次出现时 |
| 禁忌 | 与既定设定冲突的写法、不能出现的内容 | 一旦发现立刻记录 |

规矩：
- 伏笔必须先登记再埋，编号连续（F001、F002…），回收后改状态并写明回收章。
- 不改人物性格去迎合剧情；剧情要为人物的性格与动机让路。
- 任何与既有条目冲突的新内容，先改 02 再落笔，并在交付时明确告诉用户改了哪一条。

## 三、文风档案（04）——参考作品只提炼文风

用户把**其它已经完成的小说**作为材料给你时，本作只吸收它的**文风**，绝不吸收它的内容。

提炼流程：
1. 可用 `scripts/style-sample.mjs` 定位文风样段；**抽样阅读**，不整本读入上下文：开篇、中段、对白密集段、高潮段、结尾各取 1–3 段（每段 300–800 字）；大文件用 offset/limit 或按字节分段抽样。材料放在 `参考资料/`，只读不抄。
2. **按维度提炼**：叙述视角与人称/时态；平均句长与长短句分布；段落长度与断行；用词层级（书面/口语/方言）与高频连接方式；比喻与意象偏好；对白占比、提示语位置与说话方式标记；动作/心理/环境描写比例；标点与排版习惯（省略号、破折号、引号、空行）；场景切换、时间跳跃、章节收束与钩子的做法；情绪温度与幽默感；要规避的套话清单。
3. **写成可执行规则**，不要只写形容词。例：「短句为主，平均 15–20 字；每段不超过 4 行；对白占四成；心理用行为外化；每章最后一节留半句未完成的对白」。
4. **单列「不得模仿项」**：原作的人物名、地名、组织、专有名词、独有设定与具体桥段——本作只能借文风，不能借内容。
5. **写入 `04-文风设定.md`**（注明参考来源文件名与提炼日期），交用户确认后即成为本作文风；此后每章都按它写，交付前自查是否走样。
6. 用户没给参考作品时，按题材与要求定一份稳妥的默认文风写进 04，并标注「默认文风」。
7. 任何产出文件都不得抄录参考作品原文；引用只用于抽样分析、不落盘。

## 四、写作授权

03 只写剧情进度和下一步。短篇与长篇的写作授权均以 book.mjs status 的 mode、remaining、head 为准。 首次按 `references/longform.md` 的初始化步骤建账，旧书核实已定稿章号后再初始化。切换会话先读 status。短篇确认一章用 `grant 主编 REV single 1 "用户原话"`，连写使用 batch。取消用 stop，跨会话暂停用 pause。

用户确认开始或继续后，短篇默认 single 1；长篇用户未指定时按 5 章授权（grant 主编 REV batch 5 "用户原话"）。用户指定一章或其他章数时遵从其要求，每批最多 10 章。批满后等待新的确认，不自动续批。 需要 Node ≥ 22.5；优先使用 DSH 自带的 Node。低版本可退回单会话模式：无账本的作品可人工逐章确认、直接保存正文；已有账本的作品只写临时草稿，恢复支持的 Node 后再定稿。降级期间不建立第二份开关。

## 五、单章循环（每次写作都照此执行）

1. **读**：运行 book.mjs status，读取 02、03、04 及 01 中的本章条目。长篇按卷纲、实体分档和章卡定位相关材料。
2. **报**：用不超过 3 行说明本章目标、涉及人物与伏笔、文风要点。
3. **写**：一章一个文件，默认 2000–4000 字（用户有要求以用户为准）。顺序推进，不跳章、不并章、不预告下一章正文。按 04 的文风落笔，结尾留钩子。
4. **存**：短篇运行 `prepare 主编 REV short 章号 "章节/第NN章-标题.md" 02-设定圣经.md`（需要时追加 04 等路径），长篇使用 prepare publish。编辑返回的副本。
5. **更**：更新 02（伏笔、人物状态、新名词）、03（进度、下一章计划）、04（本章如有文风手法调整）。运行 commit，检查返回的剩余额度。
6. **交付**：剩余大于 0 时每章回一行并继续；归零后调用 `ask_user_question`（chapter_review），给文件路径、3–5 条摘要、伏笔变化、下一章计划和开关状态，供用户确认、修改本章或调整设定。
7. **改或续**：得到修改意见就先改本章与受影响的 02/03/04 并重新提交；得到确认（或连写未满）才写下一章。

额度用完时暂停；若提前完结或收到暂停要求，关闭剩余额度。参考作品只用于提炼文风。

## 六、质量检查清单（每次交付前自查）

- 视角与人称与 00/01 一致，通篇没有视角漂移。
- 文风与 04 的规则一致：句长节奏、段落长度、对白比例、标点习惯没有走样。
- 人物言行符合 02 中记录的性格与说话方式，不同角色的语言有区分度。
- 本章有明确的推进：至少完成一个情节点，或显著改变人物处境。
- 伏笔按登记表埋设/回收；本章新埋的已登记。
- 没有出现参考作品中的人物名、专有名词与具体桥段。
- 删掉套话式的情绪总结与空泛描写，用具体动作、细节、对白替代。
- 场景转换、时间跳跃清晰；字数符合要求；结尾钩子自然。

## 七、常见情况

- **上下文被压缩或隔天续写**：重读 02、03、04 和 status 再动笔，不要相信记忆。
- **用户要求改设定/改大纲**：先改 01/02/03（涉及文风时连 04 一起改），再继续写作，并在交付时说明改动。
- **用户一次给出多章要求**：按本书授权定稿，逐章保存、逐章更新，写满本批即停。
- **需要考据**：现实细节（地名、年代、器物、职业流程、风俗）用 `web_search` 查证、必要时 `web_fetch` 读原文；查到的关键事实写进 02 的对应条目（专有名词写进名词表），不得引入与 02 冲突的内容。
- **写完后**：整部完结时汇总 `03-进度日志.md`，检查伏笔是否全部回收或明确标记为开放，并把 04 的最终文风规则固化下来。
