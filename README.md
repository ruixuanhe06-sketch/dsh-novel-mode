# dsh-novel-mode · 小说创作模式

一个用于 **DeepSeek Harness** 的 agent preset：以「章」为最小单位写小说——写完一章停下来交给你审阅，确认后才写下一章。人物、世界观、伏笔记在**设定圣经**里，文风记在**文风档案**里，每章开写前强制重读。

它不追求「一句话生成整本小说」，而是把写长篇时那几个必然出问题的环节，拆成有工序的流程。

## 为什么需要它

让 AI 写短篇很容易，写长篇几乎一定会撞上四堵墙：

| 问题 | 具体表现 |
| --- | --- |
| **设定漂移** | 第三章的人物性格到第十一章就变了；前面设定不能飞，后面飞了 |
| **伏笔丢失** | 埋了没收，或者收了却跟埋的时候不是一回事 |
| **文风走样** | 越写越像模型默认腔调，参考作品的味道三章就散了 |
| **一口气写崩** | 一次生成十章，越到后面越水，而且你想改也改不动 |

本模式针对这四条，各给了一套机制。

## 四个核心机制

### 1. 一章一交付（默认行为）

每写完一章，模式**必须停下**，用 `ask_user_question` 把本章交给你：文件路径、本章摘要、埋下/回收的伏笔、下一章计划、当前开关状态。你选「确认继续 / 本章需修改 / 调整设定或大纲」之后才继续。

这是默认，不是可选项。

### 2. 设定圣经（`02-设定圣经.md`）

跨章事实的**唯一权威**，记录：人物（性格、动机、说话方式、关系、当前状态）、世界观规则、时间线、**伏笔登记表**（编号｜埋设章｜内容｜计划回收章｜状态）、名词表、禁忌。

规矩很硬：

- 伏笔**先登记再埋**，编号连续（F001、F002…），回收后改状态并写明回收章
- **不去改人物性格迎合剧情**，剧情为人物让路
- 任何与既有条目冲突的新内容，**先改文件再落笔**，并在交付时明确告诉你改了哪一条

### 3. 文风档案（`04-文风设定.md`）：只借写法，不借内容

你可以丢一部（或多部）已完成的小说当参考。模式只做三件事：

- **抽样阅读**：开篇、中段、对白密集段、高潮、结尾各取 1–3 段（每段 300–800 字），不把整本读进上下文
- **按维度提炼**：人称与视角、句长与长短句分布、段落长度、用词层级、比喻与意象偏好、对白占比与提示语位置、描写比例、标点排版、章末钩子、情绪温度
- **写成可执行规则**，不写形容词。例如：「短句为主，平均 15–20 字；每段 ≤4 行；对白占四成；每章最后一节留半句未完成的对白」

同时单列**不得模仿项**（原作的人物名、地名、专有名词、独有设定、具体桥段）——产出文件不得抄录参考原文。

### 4. 连写开关（逐章暂停的唯一例外）

明确说「连写 5 章」才会开启。开关状态写在 `03-进度日志.md` 顶部的「写作开关」区块，**每章开写前必读**——所以上下文被压缩、会话中断、隔天继续都不会丢。

- 单次上限 10 章
- 连写期间每章仍逐一保存、更新设定与文风、自查走样
- 写满 N 章自动关闭，回到逐章确认
- 遇到需要你决定的剧情分叉，立即中止连写来问你

## 作品目录

每部小说一个目录（默认建在当前工作目录下）：

```
<书名>/
  00-创作说明.md      灵感、题材、要求（原文 + 整理）、交付偏好
  01-大纲.md          章节清单：标题 / 目标事件 / 预计字数 / 伏笔安排
  02-设定圣经.md      ★ 跨章上下文，每章必读
  03-进度日志.md      顶部「写作开关」+ 进度、剧情位置、未回收伏笔、下一章计划
  04-文风设定.md      ★ 文风档案，每章必读
  参考资料/           参考作品（只作抽样阅读，原文不进入产出）
  章节/第NN章-<标题>.md
```

## 安装

**前置**：DeepSeek Harness（支持安装本地 bundle 的版本）；需要 Full 权限或人工批准。

**步骤：**

1. 把这个仓库放到任意位置，例如 `C:\tools\dsh-novel-mode`

2. **改一行路径**（必须，否则装完模式会显示为 broken）：

   打开 `cordis.patch.yml`，找到 `skill-filesystem` 的配置：

   ```yaml
   customSkillDirs:
     - C:/path/to/dsh-novel-mode/skills
   ```

   改成本机的实际路径（注意用正斜杠或转义反斜杠）。

   > 为什么不写成相对路径：DSH 会把这个值交给 `path.resolve()`，相对路径按**进程工作目录**解析，不同启动方式结果不同；而 `!!js` 表达式又会在 bundle 的 `baseUrl`（bundle 自己的目录）下解析失败，导致整个 preset 变 broken。绝对路径字面量是唯一稳的写法。

3. 在 DSH 里让 Agent 安装：

   ```
   plugin_manager  action: install_bundle
                   target: C:\tools\dsh-novel-mode
   ```

4. **刷新页面**（Ctrl+R / F5），然后**新建会话**，在模式选择器里选「小说创作」。

> 已有会话不会自动切换模式；模式名册是页面加载时向 Host 拉取的，不刷新看不到新项。

**卸载：**

```
plugin_manager  action: remove_bundle  target: @local/dsh-novel-mode
```

（包名见 `package.json`，安装后可改成自己的 scope。）

## 使用

新建会话选「小说创作」，第一条消息给任意组合的输入：

```
我想写一个关于末世邮差的故事
```

```
第一人称、悬疑、20 章、每章 3000 字、不要恋爱线
```

```
@大纲.md 按这个大纲写
```

```
用 @参考资料/某小说.txt 的文风来写，只提炼文风，不要用它的情节和人物
```

之后模式会：补齐只能由你决定的问题（≤3 个）→ 建立作品目录与 `00`–`04` → 把大纲与文风要点交你确认 → 写第 1 章 → 停下等你。

## 适合谁 / 不适合谁

**适合**：写长篇（10 章以上）、在意人设一致与伏笔回收、有参考文风想模仿、能接受「一章一确认」的节奏。

**不适合**：想一句话生成整本、只写短篇、不需要跨章一致性。

## 挂载的插件

`persona`、`agent-instructions`、`tool-pwsh` / `tool-bash`（按平台二选一）、`tool-fs`、`tool-fs-search`、`skill-filesystem` + `tool-skill`、`tool-ask-user`、`tool-todo`、`present`、`tool-web`（联网考据）、`compaction` 组（长篇小说必备的上下文压缩与工具结果裁剪）。

## 自定义

改 `cordis.patch.yml` 后重新安装（`remove_bundle` → `install_bundle`）：

- **关掉联网考据**：删 `tool-web` 那一行（人设里关于查证的段落一并删掉更干净）
- **改默认字数 / 交付话术**：改 `persona.config.prefix` 里对应段落
- **改显示名或排序**：改 `config.name` / `config.order`（`config.id` 保持 `novel`，它是会话记录里的标识符）
- **换技能内容**：直接编辑 `skills/novel-writing/`，`skill-filesystem` 会监视目录，无需重装

## 踩过的坑（改 `plugins` 之前先看）

子插件的 Config 校验在组装时执行，**必填字段缺失 = 该子插件激活失败 = 整个 preset 变 broken**。表现是「新会话里看不到这个模式」，设置页只留一个「加载失败」徽标（徽标里会写清是哪个插件缺哪个字段）。

| 插件行 | 必填字段 | 本模式取值 |
| --- | --- | --- |
| `persona` | `prefix` | 人设文本 |
| `agent-instructions` | `maxBytes` | `65536` |
| `tool-fs-search` | `sampleOverCapGlobResults` | `false` |
| `tool-todo` | `allowParallelInProgress` | `true` |

另外两条硬规则：

- **不要用 `!!js` 做模块解析**（`createRequire(baseUrl).resolve(...)`）——bundle patch 的 `baseUrl` 是 bundle 自己的目录
- **技能目录用绝对路径字面量**
